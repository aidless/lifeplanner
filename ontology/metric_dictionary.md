# metric_dictionary.md · 指标词典

> 每个指标九字段的操作性定义。与 `life_ontology.yaml` 同源（YAML 是机器可读版，
> 本文件是人的阅读版与设计说明）。**[草案]** 条目待主人审定。

版本：v1（2026-10-22）

---

## 为什么要词典

同一个词在不同语境下测的不是一回事。「学习质量」如果只定义成学习时长，
系统会奖励「坐在桌前」，而不是「学会了」。词典的职责是把每个词钉到
**可执行的测量步骤**上，并把「这个指标测不到什么」写清楚。

## 九字段模板

```
指标名称
操作性定义   —— 别人照做能复现的步骤
单位或评分尺度
数据来源      —— 含证据分级
更新频率
计算方法
不确定性      —— 可能错多少、往哪边错
适用边界      —— 它不测什么
可能造成的误导 —— 刷高它但实际变差的路径
```

## 重点条目的设计说明

### 学习质量 → 五个可分子维度（禁止单一时长）

| 子维度 | 操作化 | 为什么不能只用时长 |
|---|---|---|
| 理解 | 精读批注 ≥500 字/篇 | 时长不区分「读懂」与「读过」 |
| 记忆 | 间隔复习的回忆正确率 | 时长与长期保持率弱相关 |
| 迁移 | 新场景的可验证应用次数 | 学习的目标是迁移，不是输入 |
| 产出 | 由学习直接产生的可核验件数 | 产出可能来自旧知识 |
| 长期收益 | 6-12 个月后的能力参照系 | 前四项的领先指标未必等于它 |

**规则**：五个子维度**并列展示**，不合成「学习分」。
若必须排序用于决策，排序权重由主人写进本体并冻结。

### 面试转化率（工作域）

- 操作性定义：进入面试环节的投递 ÷ 定制投递总数
- 关键陷阱：分子分母都依赖「定制投递」的判定；判定标准必须事先写下，
  否则会自然漂向宽松（基线追认的典型形态）
- 与其他指标的关系：转化率下降 + 投递数上升 ≠ 变差（可能是目标上移）

### 日均睡眠（健康域）

- maintain 型：容差 ±0.8h，超出后按 max(tol, |baseline|/2) 线性衰减
- 陷阱：用中位数而非均值（抗单晚异常）；但中位数会掩盖连续熬夜——
  因此同时记录「连续熬夜天数」（decrease 型）作为互补指标
- 误导路径：早睡但质量差 → 与精力域的主观评分交叉验证

### 储蓄月数覆盖（金钱域）

- 可核验（tier3）：银行流水
- 陷阱：为刷高而压制健康/学习支出 → 触发跨域审计（金钱域与其他域的背离）

### 深度对话次数（关系域）

- **代理指标**：它代理「关系亲密度」，但代理反噬风险极高
  （凑数对话反而消耗关系）。审计规则已内置：代理 ≥0.75 而主观感受下降时告警
- 这是「可测量但不应被优化」的典型：它进面板是为了提醒，不是为了刷分

## 未定义即不测

凡未进本词典的词（「状态」「成长」「平衡」），系统拒绝量化并提示：
先写操作性定义，再谈数值。这是 `qcompile` 拒绝域外问题的依据。
