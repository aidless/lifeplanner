# FAILURE_LOG.md · 失败日志

> 纪律：每个失败记录**现象、根因、修复、留下的防线**。
> 没有防线的修复等于没修。本日志是项目最有价值的资产之一——
> 它证明系统的问题是被自己抓到的，而不是被用户抓到的。

版本：v1（2026-10-22，覆盖 2026-10-22 全天）

## F-01 价值分对 target 极度敏感（设计缺陷）

- **现象**：填入一周真实活动后，某目标价值从 0.20 涨到 5.51——
  「0..1 归一化」的分数冒出 5.5。
- **根因**：119 次提交 ÷ target=12 → progress 9.9 未裁剪；而 target 是人拍的。
- **修复**：`metrics.py` 快照层裁剪 progress 至 [0,1]；超额信息保留在原始观测。
- **防线**：报告把价值分降为「参考指标」并标注不可当读数；
  claim_ledger CL-01。
- **未解决**：target 由人拍这件事本身仍是价值分的根本局限（charter 禁止事项 1）。

## F-02 活动量冒充证据（决策缺陷）

- **现象**：空库（无观测/无校准样本/无指标）上，731 次 git 提交把
  「项目价值」撑到 55/100，裁决 `pivot`。
- **根因**：投入强度权重 0.4 且只有 git 一个信号有数据；规则没有「证据不足」分支。
- **修复**：`qone._decide` 增加拒答策略——无 tier≥2 观测 + 无校准样本 +
  无指标目标时只输出 `need_data`。
- **防线**：`tests/test_qone.py::test_empty_db_asks_for_data_not_a_number`；
  claim_ledger CL-02。

## F-03 从零训练决策头存在「内容绑定平台期」（研究阴性）

- **现象**：jev-s1 nano（1.3M）在内容匹配任务上 25k+ 样本 loss 钉在 ln(4)。
- **根因（已排除五项）**：SDPA 掩码方向 / 数据标签歧义（40% 样本带第二个选项词）/
  字节级 tokenizer 难度 / 独立 marker 内容为空 / 注意力先验缺失。
  最终判定：随机初始化下「marker→同词匹配」的注意力电路梯度近似为零，
  需要预训练先验——**这正是 Laya 建在 ModernBERT 上的原因**。
- **修复**：架构改为「打分位 = 选项末 token」+ 手写 float 掩码（无语义歧义）；
  预训练列为 jev-s1 下一步必做实验。
- **防线**：`tests/test_core.py` 双向性/掩码语义/per-question softmax 回归；
  claim_ledger CL-04 + CL-P1（待验证推论）。

## F-04 看板在无预测库上白屏（健壮性）

- **现象**：`cal.brier` 为 None 时 f-string 格式化抛 TypeError，整个看板生成失败。
- **根因**：新库必然无已结算预测，未做 None 分支。
- **修复**：`_num/_signed` 归一为 `—`。
- **防线**：`test_no_predictions_does_not_crash`。

## F-05 week 把「什么都没建」说成「一切都好」（首跑体验）

- **现象**：真实库 3 目标 0 指标，`week --plan-only` 输出「本周没有需要处理的事项」。
- **修复**：分态引导（无目标→建目标；有目标无指标→挂指标）。
- **防线**：真实库首日验证。

## F-06 act tick 对截止风险失明（覆盖缺口）

- **现象**：CASMI26 目标 53 天后截止、无指标无预测，tick 说「没有需要处理的事项」。
- **修复**：60 天内截止且无可结算事实的目标 → tier0 提议。
- **防线**：真实库首跑正确触发。

## F-07 🔴 我自己污染了真实数据库（流程事故）

- **现象**：审阅 `resolve --evidence` 时在真实库演示，写入 2 条测试预测，
  `calibrate` 随即给出「系统性过度保守」的**假结论**（n=2）。
- **根因**：操作前没有显式确认目标库路径（真实库 vs 测试库）。
- **修复**：按关键字删除测试预测与事件；真实库回到 0 预测。
- **防线**：操作真实库前先 `lifeplan doctor` 确认库路径成为硬规则；
  已写入 `docs/REVIEW-2026-10-22.md`。
- **教训**：**一个建来防自欺的系统，差点被建造者自欺。**

## F-08 清理污染时第一次没删掉（操作失误）

- **现象**：`DELETE ... LIKE '测试:%'`（半角冒号）对全角冒号「测试：」匹配 0 行，
  自以为清理成功。
- **根因**：模式串与数据不一致，且没有验证删除行数。
- **修复**：按关键字「测试」重删 + 验证 COUNT。
- **防线**：**删除操作必须带前后计数验证。**

## F-09 演示数据沿用了真实观测值（隐私疏漏）

- **现象**：开源前清洗 seed 后，第一版「虚构」数据仍含用户真实观测
  （投递 6/9/5/11/8、转化 4%、竞赛 0.45）。
- **修复**：全部随机化为中性数字；远端 clone 两轮 grep 终检。
- **防线**：开源流程固化为六步（见 charter/privacy_policy.md §6）。

## F-10 Laya 决策层在内网/高负载下不可用（环境）

- **现象**：`snapshot_download` 在线拉取走代理 → ProxyError；负载 260 时 → MemoryError。
- **修复**：`_get_agent` 优先 `local_files_only=True`；降级路径带 note。
- **防线**：适配器 status() 先查缓存；降级链 rules → abstain 有测试。
