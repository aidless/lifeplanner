## 关于「编造数字会怎样」

核验器逐字比对答复与工具结果。若模型写出「你的价值分是 0.777，名次提升到 1824」：

```
价值分是 0.777，名次提升到 1824

依据（1 次工具调用）：
  【1】plan_score → 价值分 0.3xx ...

⚠ 核验未通过：
  · 以下数字在工具结果中找不到出处：0.777、1824
```

允许四舍五入与百分数换算，其余一律判为无依据。
理由：小模型最容易犯的错不是逻辑错，而是把数字写"顺眼"——
而一个编造的分数会直接污染校准台账。

## 关于驱动

`scripted` 只做关键词路由 + 确定性拼接，**不做多步推理**。
它的价值是：保证系统在没有可用模型时仍然诚实、可追溯、可用。
接入本地模型（Ollama）或 Laya 后由对应适配器接管，代码不变。
