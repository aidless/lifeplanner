## 1. 核心命题

**「万事万物皆可量化」不是一个全称命题，而是一个有前提的工作假设：**

> 一个对象可被量化，当且仅当它满足下述全部条件：
> ① 存在**可观测变量**（能被观察或测量，而非仅被断言）；
> ② 存在**稳定的参考系**（基线、对照组、时间窗口或外部基准）；
> ③ 观测**可重复**（他人用同样方法能得到同样结果）；
> ④ 误差**可界定**（知道这个数可能错多少、往哪边错）；
> ⑤ 存在**反例通道**（能设计出一种观察，使该量化被证伪）。

不满足条件的对象**不是不可量化，而是尚未被可靠量化**——它们进
「不可量化登记表」，登记原因、复查日期与替代表达方式（偏好、意义、
价值判断），而不是被假装测出来。

**推论**：量化本身不是目的。量化的价值来自第 ⑤ 条——可证伪性。
一个不可证伪的数字不是测量，是修辞。

## 2. 系统目标

建立一个**可审计的人生操作系统**，由五部分构成：

```
人生状态面板（多轴，无单一总分）
+ 证据库（分级、带哈希、可验伪）
+ 目标系统（指标有操作性定义、基线冻结、到期可结算）
+ 决策引擎（先证据后决策，低置信拒答）
+ 行动实验与周期复盘（每次量化都可被时间检验）
```

## 3. 明确禁止事项（不可协商）

1. **不建立代表「人生好坏」的单一总分。** 实测教训：把多维压成一个标量后，
   标量本身会成为优化目标，且该标量对「当初谁写了 target」极度敏感
   （本项目实测：同样一周的生活，价值分可以从 0.29 跳到 0.73，
   唯一变量是 target 的填写值）。多维可以并列展示、可以带置信度，
   不可以合成一个「人生分」。
2. **不让模型绕过人的最终决定权。** 模型的输出是「带置信度与证据的
   建议」；tier≥2 的行动必须人工回填令牌确认；重大人生决策
   （换城市、离职、终止关系）永远由人发起并签署。
3. **不把活动量当成果。** 实测教训：空库上 731 次 git 提交曾把「项目
   价值分」撑到 55 并裁决「调整方向」——在动不等于在对。无 tier≥2
   证据时，系统只允许回答 `need_data`。
4. **不虚报来源。** 预印本不得写成「在审」，演示数据不得混入真实库，
   自述级证据必须标注为自述。
5. **不为通用性牺牲单点可用。** 先做一个垂直域做到可审计，再扩。

## 4. 角色边界（谁负责什么）

| 角色 | 负责 | 明确不负责 |
|---|---|---|
| LLM（规划器） | 理解问题、拆解任务、提出候选指标 | 算术、最终裁决、无证据断言 |
| 工具与数据库 | 取证（git/文件/网页/DB） | 判断 |
| Python/SQL/统计 | 所有数值、区间、统计检验 | 解释意义 |
| Laya/Jev 决策层 | 快速结构化判断（choice/score/noul） | 生成长文本、替代人 |
| 记忆系统 | 长期状态与历史决策 | 篡改历史（哈希校验） |
| 人 | 发起、确认、否决、定义价值 | —— |
