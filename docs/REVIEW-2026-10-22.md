## 发现与修复（4 项，均已修 + 回归）

### 1. `week` 对「有目标、无指标」误报「无需处理」〔已修〕

真实库 3 目标 0 指标，`week --plan-only` 输出「本周没有需要处理的事项」。
这是首跑体验里最糟的一种错：把「什么都没建」说成「一切都好」。
现在分三种状态分别引导：无目标 → 先建目标；有目标无指标 → 先挂指标；
两者都有 → 正常出清单。

### 2. `act tick` 对截止风险完全失明〔已修，真实目标已触发〕

某真实目标 53 天后截止，无指标、无预测，tick 说「没有需要处理的事项」。
一个到期时**无法被结算**的目标，系统不该沉默。新增 deadline 提议：
60 天内截止且无可结算事实的目标 → tier0 提议（建议先挂指标）。
真实库首跑即正确触发：

```
#1 [tier0] 目标「…」53 天后截止，但该目标下没有任何指标——
   到期时它将无法被结算
```

### 3. 审计在空库上误报〔已修〕

`value_confidence_gap`（本轮新增的第四查）在空库上把 value=0.00 的领域
判为「最高分」，输出「价值 0.00 是全部领域最高」——可笑的假阳性。
加门：`value ≥ 0.5 且 metric_count > 0` 才触发。

### 4. 预测结算没有证据位〔已修，schema v3〕

最严重的一项。`resolve` 原来只写 outcome，**结算行为本身没有任何凭据**——
校准台账会建在自述上。这与主人主旨直接冲突：「敢」登记只是开始，
结算可查证才是「不可核验的量化只值一半分」的落点。

现在 `resolve --evidence <依据> --note <备注>`：
- 有证据 → 入库并标证据等级（`tier_label` 分级）
- 无证据 → 显式降级：`⚠ 此条结算按「自述」计，对外陈述校准结论时样本量要扣除它`

## 事故：我污染了真实库（已清除，根因已定位）

审阅第 4 项时，我在真实库上演示 `predict`/`resolve`，**写入 2 条测试预测**
（p=0.70/0.60，均 hit=1）。后果：`calibrate` 立刻给出假结论
「系统性过度保守，低估了自己的兑现能力」——n=2 的假曲线。

清除过程还出了第二次错：第一遍用 `LIKE '测试:%'`（半角冒号）没匹配上
全角冒号，删了 0 条；按关键字「测试」重删后才干净。
现在真实库回到：predictions 0 / observations 0 / metrics 0 / goals 3。

**根因**：我自己的操作纪律失误——真实库上做演示前没有显式 `unset LIFEPLAN_HOME`
并二次确认目标库。**预防**：本报告 + 操作前先 `doctor` 看库路径成为硬规则；
`--evidence` 的存在让此类演示至少留痕。

教训本身有价值：一个建来防自欺的系统，差点被建造者自欺。
