# Capability Map · 能力组件地图

> 按**能力组件**比较，而不是按模型名称。每个组件独立选型、独立评测、独立降级。
> 这是阶段三的产出，也是阶段八训练专用模型时的「分头」依据。

版本：v1（2026-10-22）

## 1. 感知与信息抽取

- **职责**：从环境抽取可观测信号（git 活动、文件存在性、进程、语言栈）。
- **实现**：`presence.py`（启发式画像）+ `autopilot.py`（提案生成）。
- **外部工具**：git、文件系统、进程表。
- **可本地**：✅ 纯规则 + 子进程。
- **评测**：画像准确率（与人工标注比）、信号覆盖率（能测的指标占比）。
- **失败降级**：扫描失败 → 该信号标 unknown，不猜（实测：沙箱拦截时正确降级）。
- **已知边界**：睡眠、面试、关系类信号**推不出来**——不要造假推断（已写入 README）。

## 2. 记忆与检索

- **职责**：持久化状态、历史决策、事件流。
- **实现**：SQLite 单文件 + events/decisions/observations 表。
- **选型理由**：个人数据量级（万行）远不需要向量库；SQL 可复算、可审计、
  无嵌入模型的黑箱。检索 = 精确查询，不是语义近似。
- **外部工具**：无。
- **可本地**：✅。
- **评测**：查询可复现性（同查询同结果）、备份恢复演练通过率。
- **失败降级**：库损坏 → restore 演练（已演练：清空→恢复→数据完整）。

## 3. 计划与分解

- **职责**：把模糊问题拆成可测量的子问题。
- **现状**：v1 规则编译器（垂直域匹配，不匹配则拒答）。
- **v2 选型**：本地 3-8B LLM（Ollama），产出必须是**结构化测量计划 JSON**，
  经 `qcompile` 校验后才进入计算。
- **外部工具**：无（或联网检索）。
- **可本地**：✅。
- **评测**：拆解计划的「可执行率」（子问题能否被现有工具取证）、
  人工修正率（v1 无数据，v2 起积累）。
- **失败降级**：LLM 不可用 → 规则编译器；规则不匹配 → 显式 unknown。
- **铁律**：LLM 只提候选指标，**批准权在人**。

## 4. 工具调用

- **职责**：执行取证与写入操作，受权限门禁约束。
- **实现**：`agent/tools.py` 12 工具 × tier0-2；tier2 只生成提案，
  执行必须人工回填令牌。
- **选型**：规则路由（scripted）+ Laya choice（零参数工具快速路由）
  + LLM（需要参数时升级）。
- **可本地**：✅。
- **评测**：路由准确率（Laya 实测 0.9987 on 校准问题）、
  越权执行次数（必须为 0，测试断言 actions 表无 done）。
- **失败降级**：Laya/LLM 不可用 → scripted；工具报错 → 记 note 不中断。

## 5. 数值计算

- **职责**：**所有数值的唯一产地**。
- **实现**：`calc.py`（AST 白名单求值 + bootstrap 区间 + Brier/ECE）。
- **选型**：无模型。`__import__`/属性访问/lambda 一律拒绝（测试钉死）。
- **可本地**：✅。
- **评测**：与参考实现（numpy/scipy）逐位比对；确定性（同输入同输出）。
- **失败降级**：除零/空输入 → None + unknown，绝不猜数。

## 6. 结构化决策

- **职责**：choice/score/noul 三类快速判断。
- **实现**：`agent/adapters.py::SystemOneAdapter`（Laya）+ 规则兜底 + 拒答策略。
- **选型**：Laya（开源、Apache 2.0、32.8ms/题）；未来 jev-s1（自有权重）。
- **可本地**：✅（权重已缓存 647MB；内存不足时降级，实测 MemoryError → rules）。
- **评测**：各题型准确率、**选项顺序不变性**（阶段八测试项）、
  校准（ECE per qtype）。
- **失败降级**：置信 < 0.60 → 升级 LLM；LLM 不可用 → 规则；证据不足 → 拒答。

## 7. 不确定性估计

- **职责**：区间、置信度、拒答门。
- **实现**：`calibration.py`（Brier/ECE/过度自信/分箱）+ `calc.bootstrap_ci`。
- **选型**：统计方法，不用模型自评（模型自评的置信度不可信——CL-03 演示数据
  显示 +0.17 过度自信）。
- **可本地**：✅。
- **评测**：ECE（目标 < 0.20）、可靠性分箱偏差、拒答后人工修正率。
- **失败降级**：n < 5 → 不报区间，只报 unknown + next_measurement。

## 8. 反思与纠错

- **职责**：发现「自欺」：基线追认、代理反噬、证据通胀、高分低置信。
- **实现**：`audit.py` 四查 + `week.py` 周复盘。
- **选型**：规则为主（可复算），LLM 辅助解读（v2）。
- **可本地**：✅。
- **评测**：发现的问题中「人工确认有效」的比例；漏报率（人工回放）。
- **失败降级**：规则漏检 → 周复盘由人过一遍（人永远是最后一道）。

## 9. 长期目标管理

- **职责**：目标-指标-基线-期限的结构；到期提醒；deadline 风险。
- **实现**：`metrics.py` + `autopilot.propose_from_plan`（60 天截止风险提议）。
- **可本地**：✅。
- **评测**：到期目标的可结算率（有指标有观测的比例）；
  实测教训：CASMI26 类目标曾无指标到截止（已修）。
- **失败降级**：无指标目标 → deadline 提议 + week 引导，不静默。

## 10. 隐私与权限控制

- **职责**：数据不出本机；危险动作需人确认。
- **实现**：SQLite 本地 + `policy.py` 五级门禁 + `terminal.py` 令牌确认 +
  开源泄漏扫描流程。
- **选型**：架构保证，不是模型承诺。
- **可本地**：✅（唯一不依赖任何外部服务的组件）。
- **评测**：高危命令拦截率（测试断言 sudo/rm -rf 拒绝）、
  开源发布前泄漏扫描（已执行三轮）。
- **失败降级**：策略文件损坏 → 默认拒绝（fail-closed）。

## 组件间的接口（数据流）

```
用户目标 ──→ 量化编译器 ──→ 测量计划（typed questions）
                                   │
              证据 Agent ←─────────┤（需要什么证据）
                   │               │
                   ▼               ▼
              证据库（sha256）──→ 计算引擎 ──→ 数值+区间
                                   │
                                   ▼
                          Laya/Jev 决策层 ──→ choice/score/noul
                                   │
                                   ▼
                    不确定性层（置信度×证据覆盖）──→ 拒答门
                                   │
                                   ▼
                    行动建议 ──→ 人工门控（tier≥2）──→ 执行
                                   │
                                   ▼
                          溯源账本 + 周期复盘（回到目标）
```

**没有箭头的地方就没有信任传递**：计算层不接收模型输出作为输入，
决策层不接收未标证据的数字。这是整个架构最重要的一条。
