## 1. 基础模型：开放生态的现状

**发现**：2023-2024 后，「开放权重」已细分为三档——权重开放（Llama/Qwen/DeepSeek）、
数据+代码+中间检查点全开放（OLMo 2，A 级）、完全闭源仅 API（Jev）。
对 Q-One 的含义：**规划器选型只需考虑前两档**，决策层（Laya）已够开放。

**可迁移**：数据混比方法论（Llama 2/3）、MoE 负载均衡（DeepSeek-V3）、
数据质量>规模（Phi-3「教科书」数据）、蒸馏降级路径（DistilBERT）。

## 2. 训练方法：从 RLHF 到可验证奖励

**主线**：RLHF（InstructGPT）→ DPO（闭式替代 RL）→ GRPO（可验证域免 critic）→
过程奖励（PRM800K）。趋势是**奖励越来越贴近可验证信号**。

**对 Q-One 的含义**：人生决策的「奖励」大多是延迟且不可验证的——
这决定了阶段八训练必须以**校准**（Brier 为 reward，RLCD 路线）而非
结果奖励为主。否则模型会学会「说得好听」而不是「说得准」。

## 3. Agent：从 ReAct 到可信行动

**谱系**：ReAct（思考-行动循环）→ Toolformer（自举工具调用）→
Reflexion（语言化反思）→ Voyager（技能库）→ SWE-agent（专用接口）→
Generative Agents（记忆流）。

**对 Q-One 的可迁移组件**：
- 循环协议 = `agent/tools.py` 的 12 工具 + tier 门禁
- 反思记忆 = `week.py` 周复盘 + `audit.py` 四查
- 技能库思想 = `capability_map.md`（能力可复用，不是模型可复用）
- 专用接口 = CLI 本身（SWE-agent 的教训：接口设计决定 Agent 上限）

**边界**：所有 Agent 论文都**没有解决**「指标是否合理」——
那是量化编译器（本项目的层）的职责，不是 Agent 的。

## 4. 检索与记忆：为什么本项目不用向量库

**证据**：Lost in the Middle（A 级）证明长上下文利用不均——
关键证据应放首尾；LLMLingua 证明压缩可行。

**决策**：个人数据量级（万行）用 SQL 精确查询。语义近似检索引入
不可复算黑箱，与原则「可复算」冲突。若未来接入论文库，
先做混合检索并保留精确查询路径。

## 5. 决策模型：Jev/Laya 的定位与证据

**核心结论（B/C 级，待独立复现）**：
- Jev = TypeSafe 托管 System 1 决策 API（D 级能力证据：无独立复现）
- Laya = 开源对标（Apache 2.0），ModernBERT 骨干 + 决策头 + RLCD 训练，
  T4 上 32.8ms/题；**零样本接近随机**（typed-decisions 0.362 vs 随机 0.318），
  出厂过自信（ECE 0.466，温标重校后 0.081）
- 官方自定位：「a fast base to specialise, not a zero-shot decision engine」

**本项目的独立贡献（A 级，可复现）**：
从零训练（无预训练）的决策头存在**内容绑定平台期**（CL-04）——
这为「Laya 为何必须建在预训练骨架上」提供了机制层面的解释。

## 6. 校准与拒答：本项目最直接的理论武器

- Temperature Scaling（A）：出厂过自信的标准补救，本项目已实现
- ECE 无偏估计（A）：分箱敏感性必须报告
- Learning to Abstain（A）：拒答的理论依据，本项目 `need_data` 门的来源
- Conformal Prediction（A）：分布无关区间，当前用 bootstrap，
  覆盖率为边际保证时切换

## 7. 人生系统：技术之外的另一半

五篇（A 级元分析/经典）：执行意图（if-then 计划）、目标设定（具体+困难）、
SWLS（幸福感量表）、系统思维（存量流量反馈延迟）、前景理论（参考点依赖）。

**共同指向**：行为改变的证据强度远低于模型论文——这要求人生系统的
「有效性」必须用纵向实验证明，不能引用类比。这正是
`benchmark_spec.md` §3.4 存在的原因。
