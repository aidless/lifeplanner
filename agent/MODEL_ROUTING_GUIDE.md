## 2. 为什么不让 LLM 做结构化判断

1. **贵**：一次 choice 判断，33ms vs 数秒
2. **不准**：LLM 的「选 A」不可校准；Laya 的 noul 输出是概率
3. **不可复算**：LLM 同输入不同输出；决策层必须确定性（固定 seed）
4. **选项顺序敏感**：LLM 有明显位置偏置；Laya 每选项独立打分（顺序不变性可测）

## 3. 为什么不让 Laya/小模型做规划

它们**不会生成计划**——System 1 决策模型的输出空间就是候选集。
让它们做规划等于让计算器写诗。

## 4. 升级链（escalation）

```
Laya 置信 ≥ 0.60 ──→ 采用（decided_by=laya）
Laya 置信 < 0.60 ──→ 升级 LLM（note 记录原因）
LLM 不可用 ──────→ 规则（decided_by=rules，阈值文档化）
证据不足 ────────→ 拒答（decided_by=abstain，优先于以上全部）
```

## 5. 本地模型选型（2026-10-22 实测，CPU）

| 模型 | 首token | 可用性 |
|---|---|---|
| llama3.2:3b | 8.8s（含加载） | ✅ 默认规划器 |
| qwen3:8b | >180s 超时 | ❌ CPU 不可用，有 GPU 再考虑 |

决策层权重已缓存（`convaiinnovations/laya-multilingual`，647MB），
高负载机器上可能 MemoryError → 自动降级（设计行为，非故障）。

## 6. 成本意识

- 个人系统日均决策 < 50 次：Laya 成本 ≈ 0；LLM 成本取决于本机
- 不为「偶尔的难题」常驻大模型——按需升级，用完释放
